# Chapter 8: conditional release plan

Status: NOT_EXERCISED. No release card, frozen protocol, qualification receipt or
historical acceptance is rewritten by this chapter. Current user instructions
prohibit images and worker contact; neither model visual review nor independent
Sol/Terra acceptance is claimed.

When the user separately authorizes release work:

1. Reconcile and review both repositories' complete chapter changes. Establish
   immutable backend/UI commits, a release version and exact candidate inputs.
   Preserve unrelated work. A wheel made from this dirty development tree is not
   a frozen release candidate. Do not push without authorization.
2. Read the current canonical WO40 roadmap and `release/qualification.toml`,
   `release/platforms.toml`, `release/artifact_layout.toml`,
   `release/requirements.lock`, `release/performance_thresholds.toml`, and locked
   runner-source identities. Resolve the UI application's packaging addition
   through the release owner; existing terminal artifacts do not qualify it.
3. Freeze exact product/dependency wheels, licenses and candidate/source hashes.
   Check offline install/upgrade preservation in fresh roots on each supported
   target: macOS arm64 and Linux x86_64, CPython 3.14. Windows is unsupported by
   the frozen platform protocol. Verify protected entry points, installed data
   resources, first use, clean exit, backup/restore and incompatible-version refusal.
4. Execute the canonical evidence order WO40-D1, E, F, G, H, I, J only with their
   actual prerequisites and approved environments. The designated performance
   target is macOS arm64. Follow the frozen one-attempt/fresh-root retry policy;
   do not recast focused UI tests or Chapter 8 measurements as qualification.
5. Resolve crash/cleanup and publication failures causally at the owning seam.
   Rebuild changed candidates and attach exact source/candidate/runner receipts.
   Retain failed attempts. Never replace platform execution with local inference.
6. Request a separate human usability decision when authorized. Image-based work
   must remain unrun unless the user's image prohibition is explicitly lifted.
   Assess readability, keyboard focus, minimum dimensions and 115% scale on the
   actual display. Keep model/offscreen, human, learning and release statuses apart.
7. Publish the supported capability/limitation matrix and only then perform any
   separately authorized signing, distribution or push. Real-market calibration,
   brokerage, portfolio expansion and the office game remain future decisions.

The Chapter 8 functional proof is reproducible from its installed-package and
source-bound receipts. It can support candidate review; it does not satisfy these
unrun release gates or demonstrate trading profitability/learning effectiveness.
